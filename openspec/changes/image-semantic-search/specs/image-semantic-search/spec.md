## ADDED Requirements

### Requirement: 自然语言图片搜索

系统必须（SHALL）允许用户使用自然语言文本查询来搜索工作区图片，并必须按匹配分由高到低返回结果。

#### Scenario: 查询返回排序结果

- **WHEN** 用户输入非空查询（如"箭头图标"）并触发语义搜索
- **THEN** 系统为每张已索引图片计算匹配分，并按分数降序返回前 N 张图片，每张附带其匹配分

#### Scenario: 没有图片超过阈值

- **WHEN** 没有任何已索引图片的匹配分达到或超过最低分阈值
- **THEN** 系统返回空结果集，界面展示"无匹配结果"状态而非报错

#### Scenario: 空查询

- **WHEN** 用户清空语义查询或提交空/纯空白查询
- **THEN** 系统不执行语义搜索，面板回到默认（非语义）的图片列表

### Requirement: 中文查询处理

系统必须（SHALL）检测以中文为主的查询，并在 CLIP 文本编码前将其翻译为英文；若翻译失败，必须回退到原始查询文本。

#### Scenario: 中文查询被翻译

- **WHEN** 查询主要由 CJK 字符组成（占非空白字符的一半以上）
- **THEN** 系统将查询翻译为英文，并使用该英文文本进行 CLIP 文本编码

#### Scenario: 翻译失败时回退

- **WHEN** 中文查询的翻译抛出异常或返回空
- **THEN** 系统使用原始查询文本进行编码，仍返回结果且不抛出致命错误

### Requirement: 混合匹配评分

系统必须（SHALL）使用可配置权重将 CLIP 语义相似度与 OCR 关键词覆盖率分数结合，并按综合分对结果排序。

#### Scenario: 应用综合分

- **WHEN** 已索引图片存在 OCR 文本且 OCR 权重已启用
- **THEN** 每张图片的最终分为 `(1 - ocrWeight) * clipScore + ocrWeight * ocrScore`，并按该最终分排序

#### Scenario: OCR 禁用或不可用

- **WHEN** 配置中禁用了 OCR，或某图片不存在 OCR 文本
- **THEN** 系统仅按 CLIP 语义相似度对图片排序且不失败

### Requirement: 搜索界面集成

图片面板必须（SHALL）提供进入语义搜索模式的入口（区别于现有文件名过滤），必须在索引或下载模型时展示进度，并必须展示每个结果的匹配分。

#### Scenario: 用户切换到语义搜索

- **WHEN** 用户在图片面板激活语义搜索并提交查询
- **THEN** webview 将查询发送给插件，待结果返回后渲染排序后的图片及其匹配分

#### Scenario: 长耗时操作期间的反馈

- **WHEN** 一次搜索需要下载模型或首次构建索引
- **THEN** 界面展示进度/加载反馈并保持响应（用户可取消或继续浏览）而非卡死

#### Scenario: 选择结果

- **WHEN** 用户点击某个搜索结果
- **THEN** 该结果继续支持现有图片的定位/预览/拖拽等行为
